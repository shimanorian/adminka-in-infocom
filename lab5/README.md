## Логи и маппинг

40 логов я сгенерировала с помощью AI: четыре сервиса, уровни INFO, WARN, ERROR, у части одинаковые trace_id. Файл `logs.ndjson`.

Маппинг: время это date, сообщение это text, уровень, сервис и trace_id это keyword. Text режется на слова, по нему ищут слово в тексте. Keyword хранится целиком, по нему точный фильтр и подсчёт групп.

![Маппинг](screenshots/07-mapping.png)

## Ротация индексов

Если всё писать в один индекс, он растёт бесконечно, а старое удалять долго. Поэтому делают так: индекс набрал сколько-то, создаётся новый (rollover), а старые удаляются по расписанию (ILM). Приложение пишет в alias, такой псевдоним, который всегда показывает на текущий индекс.

Политика: новый индекс после 10 документов, удаление через 30 минут. Порог маленький, чтобы быстро проверить.

```
PUT _ilm/policy/app-logs-policy
{
  "policy": {
    "phases": {
      "hot": { "actions": { "rollover": { "max_docs": 10, "max_age": "1d" } } },
      "delete": { "min_age": "30m", "actions": { "delete": {} } }
    }
  }
}
```

## Мониторинг

Поставила elasticsearch_exporter, Prometheus и Grafana, как в прошлой лабе. Хотя я с ними уже работала, всё равно было тяжело понять, что там вообще происходит, интерфейс у них очень запутанный. Сначала даже не поняла, где «делать метрики». Оказалось, экспортер их уже собирает, нужно только сделать панели в Grafana.

![Targets](screenshots/22-prometheus-targets.png)

На дашборде статус кластера, неразмещённые шарды, heap, свободный диск, документы по индексам и скорость записи. С документами был затык: запрос `elasticsearch_indices_docs{index=~"app-logs.*"}` выдавал No data. Это метрика всего узла, по индексам нужна `elasticsearch_indices_docs_primary`.

![Дашборд 1](screenshots/23-dashboard-1.png)

![Дашборд 2](screenshots/24-dashboard-2.png)

![Дашборд 3](screenshots/25-dashboard-3.png)

По графикам: в `000001` 40 документов, в `000002` ноль, ротация сработала. Heap дорос до 65% и упал до 15%, это Java почистила память. Диска свободно 93,7%, кластер green.

Для алертов я сначала выбрала статус и свободный диск, а третьим документы по индексу. Но документы растут при нормальной работе, на них непонятно какой порог ставить. Правильнее heap. Итого:

1. Статус кластера: red сразу, yellow если дольше 10 минут. Red значит часть логов недоступна.
2. Свободный диск меньше 20%. На 95% эластик переводит индексы в read-only и логи перестают писаться вообще.
3. Heap больше 85% дольше 5 минут. Когда память кончается, всё тормозит, запросы отклоняются, а эластик может упасть.
